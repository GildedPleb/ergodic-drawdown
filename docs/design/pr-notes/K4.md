# K3 + K4: rings and targets on rows with a description (V32-BUILD:862–863)

Grading notes for Probe. Default size only; every large-size part (the large mark, the colour
picker, F1) is on hold for Form's large-format spec.

## RECORDED EXCEPTION to H1 (44px)

**Number rows** (Volatility, Samples, Years, the model variable, +/−): the tap target is the row's
label band, not a 44×44 box. Per K4 (4) it is the full row width (tapping the row opens its field,
:198), at least 24px tall (WCAG 2.5.8 AA), and it never reaches the description. Grade these at
**≥24px**, not 44px. G7 (`expectTapTargets`) applies 24px only to an element with a
`label[data-target="row"]` band; everything else keeps 44px.

**Clamp** keeps H1: each toggle's target is 44px.

## How it is built

- **Rings stay in the label track.** Clamp's ring is inside its button (`outline-offset` minus
  `--focus-w`, through a local `--_in`, since R4 bars `calc()` in lengths) around the box and words. A number row's ring is inside its value
  cell, which is exactly the track tall. Neither leaves the track at 390 or 1440, 100% or 200% text.
- **The description sits above the hit area.** Every target is an earlier sibling (or the
  control's own `::after`; K1's test bars `::before` in TickToggle), so the label, the value and the description paint over it, and none
  of them overlaps a target anyway. A tap on description text toggles and opens nothing; this
  fixes the Clamp flip.
- **Clamp:** the button is the 28px track tall and ends on its bottom edge; its `::after` rises
  `--s-5` (16px at 100%, 2 × `--s-2`) into the gap above, so the target is 44px at 100% (88px at 200%), anchored to the track
  bottom. R6 bars margins, so when the pair wraps at 200% (Min, then Max) its row gap is `--s-5`:
  each line's 16px rise stays clear of the line above (the lines are 44px apart at 100%).
- **Number rows:** `LedgerRow` renders an empty, `aria-hidden` `<label for=… data-target="row">`
  first. It spans the row's first grid track (both tracks when the row stacks under 16rem), the
  full row width including the mark column (no `grid-column`, so the padding box), and 16px up into the gap.

## Interpretation for Form to confirm

K4 (4) says the number-row target is "centred on the track and ends where text begins above and
below". The description starts at the track's bottom edge (0px of space below it), so a band
centred on the 20px track that never meets text below is 20px tall, under the ≥24px floor. The
build reads "ends where text begins" as the binding rule: the band ends at the track bottom (the
description's top) and rises 16px above it, the same anchoring as Clamp. That makes it 36px at
100% text on a one-line label (more when the label wraps; 107px at 200% at 390). The rise is
`--s-5` (16px at 100%, scaling with text), inside the space between rows (17.5–24px at 100%), so
it never meets the text above.
